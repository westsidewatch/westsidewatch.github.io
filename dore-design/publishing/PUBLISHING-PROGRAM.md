# Westside Publishing Program

Status: ACTIVE UMBRELLA PRODUCT PROGRAM
Established: 2026-09-03

## 1. Decision

Use **one publishing program with two independent book product projects**, each bound to its own primary Doré loop.

Do **not** collapse the books into one project. Do **not** leave them as unrelated standalone projects either.

Architecture:

**WESTSIDE PUBLISHING PROGRAM**

→ **BOOK 01 — 《聖靈也會參與設計嗎？》**
   - primary loop: New Westside / Brand Bible / visual-learning / Storybook product loop
   - product form: design textbook + theological reflection + gospel witness + interactive/printable book + Journal special issue

→ **BOOK 02 — 《神很遠 神很近：天國語言極簡史》**
   - primary loop: 黎明書局 / language / reading-writing product loop
   - product form: 50,000–100,000-word theological narrative book, eventually Chinese-English bilingual, with a Journal illustrated special based on its outline/argument arc

The publishing program supplies common editorial infrastructure but does not erase each book’s theological thesis, loop, source corpus, visual language, manuscript voice, evidence or acceptance criteria.

## 2. Why this architecture

The two major loops now have corresponding publishable outcomes:

- **Visual / design learning loop → Book 01**
- **Library / language / writing loop → Book 02**

This creates a useful Doré principle:

> **Major learning loops should be capable of producing durable cultural products, not only improved internal capability.**

The publishing program is therefore an orchestration layer. The books remain product owners.

## 3. Shared publishing services

The parent program owns reusable infrastructure:

- manuscript/version archive;
- source/provenance registry;
- Scripture/source citation discipline;
- theological review and claim-strength labeling;
- Chinese editorial style;
- English translation/style development;
- bilingual editorial alignment;
- print typography research;
- HTML book engine;
- print CSS / paged-media pipeline;
- PDF/print proofing standards;
- image rights/provenance;
- accessibility;
- Journal adaptation framework;
- editorial metadata;
- ISBN/publication preparation if later needed;
- conversation/research archive;
- common source boundaries.

The parent program must never force the two books into one visual style.

## 4. Spiritual/theological source boundary

Canonical boundary:

`dore-design/projects/new-westside-visual-construction/SOURCE-BOUNDARIES.md`

No idol-centered, Buddhist, occult, New Age, spiritist, syncretistic or unrelated devotional source is to be used as a theological/visual authority for these publications. Avoid importing religious symbols merely as attractive visual material.

For secular design/history research, prefer official, original-rights-holder, library, museum, publisher, institutional or neutral scholarly/design sources.

## 5. Book-to-Journal principle

A Westside book is not merely exported into Journal after completion. Each book should generate Journal material during research.

**Book manuscript → chapter architecture → visual/editorial studies → Journal special issue → reader entry into full book.**

Journal adaptation is therefore a publishing surface, not a summary brochure.

## 6. Digital / print duality

The publishing program treats HTML and print as two expressions of one editorial source.

Goal:

**one structured source → interactive HTML book → print-ready paginated edition → Journal adaptation.**

The web edition may exploit interaction, doors, thresholds, movement, layering and navigation, but the underlying editorial hierarchy must remain printable.

Where possible, design decisions should have both:
- an interactive/web behavior; and
- a static print equivalent.

## 7. Doré publication loop class

Class: `PUBLISHING_ORCHESTRATION_LOOP`

It is not a generic learning loop and not the owner of book content.

Responsibilities:
1. detect publication-producing outputs from child loops;
2. route them to the correct book;
3. preserve sources and conversation provenance;
4. enforce manuscript output, not learning-only completion;
5. run editorial/technical checks;
6. maintain HTML/print/Journal surfaces;
7. prevent cross-book contamination of thesis or voice;
8. coordinate reusable infrastructure.

Book-specific loops remain authoritative for subject-matter development.

## 9. Program acceptance

The parent program is healthy when each major loop is producing:

**learning → evidence → manuscript → designed publication surface → revision**

rather than producing only internal notes.

The program itself does not declare a book finished. Each book has independent completion criteria and user editorial approval.
