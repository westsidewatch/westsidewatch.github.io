## 1. Classification

This is a **child product loop**, not a peer research loop.

It differs from ordinary Doré learning loops in three ways:

1. it must continuously learn from external mature brand-bible / VI / CI / design-system sources;
2. each learning cycle must write durable manuscript material and produce visual experiments;
3. its completion target is a real publishable product: **Book 01 — 《聖靈也會參與設計嗎？》**, together with its New Westside design system, interactive/print publication, and Westside Watch Journal special issue.

Therefore this loop is nested under Book 01, while Book 01 participates in the broader Westside Publishing Program. It may consume results from broader Doré museum/design/skill/research loops, but its acceptance criteria are product-oriented.

## 4. Recurring cycle

Each iteration follows:

**Select source family → inspect complete source → map architecture → identify governing theory → study layout/typography/page sequencing → write source dossier → derive transferable methods → reject surface-copy temptations → create original Storybook experiment → browser evidence → critique → write manuscript passage → update New Westside theory → update Book 01 publication design → queue next source/experiment.**

A cycle with only web notes is incomplete.
A cycle with only a visual experiment is incomplete.
A cycle with only manuscript prose is incomplete.

The minimum complete cycle has all three:

- **learning evidence**;
- **visual evidence**;
- **written product output**.

## 5. Source families

The loop rotates through families so it does not become trapped in one tradition:

### Modern living brand bibles
Dropbox, IBM Design Language, MIT, UC, Barbican, GOV.UK, NASA current Brand Center.

### Historic CI / VI manuals
NYCTA, EPA, NPS/Unigrid, NASA historic standards and other verified high-quality corporate-identity manuals.

### Editorial/cultural systems
Guardian, Barbican, museum/cultural publishing systems and future verified editorial systems.

### Product/technical design systems
Apple HIG, Material, Atlassian, Carbon, Fluent, USWDS, BBC GEL, WCAG, DTCG.

### Generative identity case studies
Pentagram and other high-quality identity studios/case studies where system logic and applications are visible.

### AI-readable design knowledge
DesignMD, getdesign.md, Open Design and verified DESIGN.md ecosystem tools, always treated as independent analyses unless official.

### Visual museums
SiteInspire, Land-book, Godly, Awwwards, Httpster, One Page Love, Mobbin and other verified sources. These expand visual language but do not substitute for brand-system theory.

All source-family use remains subject to the project’s theological/source boundaries. Formal design learning must not import idol-centered or unrelated sacred content into Westside visual language.

## 6. Required outputs per iteration

### A. Source dossier
Must include:
- source URL/version/date when exposed;
- document/site architecture;
- narrative order;
- governing design philosophy;
- how identity becomes rules;
- how rules become applications;
- typography/layout/color/material/imagery/motion observations;
- do/don’t or equivalent teaching devices;
- governance/maintenance if present;
- what New Westside can learn;
- what must be rejected.

### B. Layout / publication study
Study the guideline as an *artifact*:
- cover/entry;
- table of contents / navigation;
- chapter rhythm;
- spread/page hierarchy;
- specimen treatment;
- diagrams;
- captions;
- margins;
- indexes;
- transitions;
- use of negative space;
- balance of prose and examples;
- print/digital differences.

This study is explicitly allowed to feed Storybook visual learning and the HTML/print Book 01 publication design.

### C. Storybook transfer
Build an original New Westside experiment from the *method learned*, not the source style.

Examples:
- after Dropbox: test whether one Westside generative device can organize many contexts;
- after Barbican: test freedom inside a small number of strong constraints;
- after NYCTA: test typographic hierarchy/signposting discipline;
- after Guardian: test editorial color as metadata/navigation rather than decoration;
- after IBM: test layout as brand point-of-view;
- after GOV.UK: test expressive range by context while preserving one identity;
- after Pentagram generative cases: test multiple radically different expressions from one core rule.

Every transfer must use Westside content or a controlled Westside-specific specimen.

### D. Manuscript product
Each iteration writes a book-quality passage. Not bullet-only research notes.

Required teaching chain:

**Observation → Principle → Reason → Rule → Counterexample → Experiment → Evidence → Revision → Transfer.**

The passage must be tagged for likely destination:
- DESIGN_TEXTBOOK
- THEOLOGY
- GOSPEL_WITNESS
- JOURNAL_SPECIAL
- CROSS_LAYER

### E. Publication-design delta
Record what the study changes in the book as an artifact:
- HTML open-book / gate / city experience;
- spread/page sequencing;
- print equivalent;
- diagrams/specimens;
- navigation/indexing;
- Journal special presentation.

### F. Theory delta
Record:
- what Westside theory changed;
- what was strengthened;
- what was rejected;
- what remains unresolved;
- whether the Visual Constitution requires a separately approved revision.

## 7. Product milestones

### M1 — Reference corpus established
Durable source registry exists, sources are classified, provenance is preserved, and Doré can rediscover them without chat history.

### M2 — Brand-bible anatomy learned
Doré can explain multiple mature ways of structuring a brand bible / CI / VI manual and distinguish specification, theory, case study, governance and application.

### M3 — Publication grammar learned
Doré demonstrates mature page/spread/navigation/specimen/diagram sequencing through original book/Journal studies.

### M4 — Cross-source theory written
A substantial chapter explains what mature brand systems have in common, where they differ and how New Westside must go beyond them.

### M5 — Storybook transfer library
A growing set of original visual experiments proves that external learning materially expands Doré’s visual vocabulary without copying external brands.

### M6 — Book 01 prototype
A complete prototype publication structure exists with real prose, diagrams, specimen pages, design-system rules, theological reflection, gospel trajectory and HTML/print mapping.

### M7 — Multiple mature New Westside website/book templates
The same core theory generates materially different complete visual systems/pages.

### M8 — Book / Journal product
The accumulated work is edited into Book 01 and the Westside Watch special issue, including 《守望，一座光明的城》 as a major exhibition/entry surface.

## 8. Loop-level acceptance gates

A source is not DONE because a URL was visited.
A theory is not DONE because Doré summarized it.
A visual lesson is not DONE because a screenshot exists.
A manuscript section is not DONE because prose exists without evidence.

For each iteration require evidence of:

1. source actually inspected;
2. architecture documented;
3. transferable principle written;
4. anti-copy/rejection judgment written;
5. Storybook or equivalent visual transfer when visually applicable;
6. deterministic browser evidence for interactive/web experiments;
7. manuscript passage written;
8. publication-design delta recorded;
9. theory delta recorded;
10. outputs linked from project index/reference registry.

## 9. Relationship to other loops

This child loop may ingest:
- museum/design-language discoveries;
- design-history curriculum;
- DESIGN.md analyses;
- color/token research;
- typography research;
- accessibility research;
- Storybook infrastructure;
- Doré Design editor outputs.

But it has a different end condition from general learning loops:

> **General loop goal: improve Doré.**
>
> **This child loop goal: improve Doré while producing Book 01 / New Westside visual system / Journal as a real product.**

Learning is therefore a means and a product simultaneously.

## 10. Non-negotiable preservation

All significant project dialogue, source lists, source dossiers, manuscript passages, rejected designs, Storybook experiments, user critiques and theory revisions remain durable project material.

Do not let a web reference live only in chat.
Do not let a visual experiment live only in a screenshot.
Do not let a learning claim exist without writing.
Do not let a failed direction disappear if it teaches something useful for the book.
