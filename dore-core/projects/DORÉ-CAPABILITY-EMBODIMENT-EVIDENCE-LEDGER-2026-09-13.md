## Current governing interpretation

These documents define architecture, not a completed implementation milestone.

Doré remains one persistent intelligence. Products, projects, faculties, runtimes and providers must not become separate Doré identities by convenience. Product boundary is not intelligence boundary; provider boundary is not intelligence boundary. Shared semantics, memory, judgment, provenance, permissions and verification should converge upward into Doré Core when they are genuinely cross-product.

The capability-embodiment doctrine is therefore classified `CORE/CONTINUOUS / ACTIVE_ARCHITECTURE`, with implementation evidence evaluated separately.

## Durable architecture rules

1. **One Doré, not a federation of mini-agents.** Image, Design, Search, Editor, Librarian and other faculties are capabilities of one intelligence unless isolation/concurrency/security genuinely requires a separate agent.
2. **Sparse activation.** Runtime should activate the minimum relevant capability set instead of loading every skill, prompt, provider or project memory.
3. **Three-speed execution.** Deterministic L0 behavior should handle resolved operations; L1 should resolve compact semantic routing; L2 should be reserved for genuine deliberation and then hand execution back down where possible.
4. **Typed artifacts over conversational handoff.** Cross-capability state should move through inspectable typed artifacts such as `VisualBrief`, `StyleRecipe`, `AssetCandidate`, `CritiqueResult`, `DesignPatch` and `VerificationResult`, not recursive free-form agent chat.
5. **Projects train; capabilities remain.** A project may close after its transferable ability is verified and promoted into the registry/reflex path.
6. **Products remain product-owned where semantics are local.** Page layout, local UI state, one-off visual composition and product-only schemas should not inflate Core.
7. **Providers are replaceable.** Local models, renderers, GitHub, Cloudflare and other execution substrates do not own Doré identity.
8. **No second brains.** Search, ONE, Design, Image, Multiwrite, Journal, Dawn Library and future products should consume shared Core capability rather than accumulate duplicate memory/judgment/control semantics.

## What is already evidenced

- A machine-readable Capability Registry exists and is used by Core-owned lookup/discovery paths.
- Reflex v0 has a verified request-scoped projection runtime with canonical-source identity and no persisted second substrate.
- The bounded Storybook autonomous-loop acceptance demonstrates one real failure → reusable repair skill → verification → resumed parent goal → terminal PASS episode.
- Product/relationship registry work has made product/project/provider boundaries explicit enough to audit rather than leaving them implicit.

These are meaningful implementation slices, but they do not prove the full embodiment architecture.

## Missing acceptance evidence

The architecture itself names measurable gates that remain unproven as a complete set:

1. a real visual task routes through image + design capabilities without free-form inter-agent chat;
2. a non-visual task demonstrably avoids loading image/design skill bodies or renderer schemas;
3. adding a dormant capability causes negligible ordinary-run latency/context increase;
4. Design and generation inspect the same typed artifact state without duplicated visual memory;
5. a repeated validated workflow demonstrably compiles downward, requiring fewer reasoning/model calls over time;
6. capability-routing failures reliably return into Reflex/regression handling;
7. resource telemetry persists active capability count, model calls, latency, context/memory footprint and cache behavior;
8. the stated bounded-activation target (ordinary median active capabilities <= 3; complex product tasks <= 6, excluding deterministic verification functions) has no persisted benchmark evidence in this sweep batch;
9. the `DORÉ-SYSTEM-RELATIONSHIP-MAP-v1` immediate reconciliation program is only partially implemented: canonical runtime-root convergence, one registry, shared acceptance vocabulary/evidence envelope, consumer declarations and retirement of obsolete bridges still require per-item proof rather than architecture prose.
