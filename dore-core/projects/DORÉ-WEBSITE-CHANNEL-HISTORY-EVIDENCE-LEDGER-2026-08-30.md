**Classification:** `MAINTENANCE / HISTORICAL IA` under the existing Main-site stewardship surface, not a new active workstream.

### 2. Dawn Library page is an older presentation shell for the canonical Library workstream

`content/website/dawn-library.md` already describes 黎明書局 as an editorial/curatorial resource system rather than a URL list and explicitly says its first version exposes整理過的 Bible/study resources while more cards/spectrum/curation would be restored later.

**Classification:** `SUPERSEDED AS ROADMAP / MAINTAINED AS PRESENTATION SHELL`.

**Governing interpretation:** Library evolution belongs to `LIBRARY-INGEST`, `3MS`, and `LIBRARY-V1`; the old content page remains provenance/presentation unless deliberately replaced.

### 4. Newsletter is explicitly future-only and should not count as an active distribution implementation

### 5. Podcast and Video are reserved future channels, not products already underway

### 6. Watch Prayer is a distinct content-series concept, but current evidence does not prove a running web series

**Classification:** `PARKED / READY-TO-REASSESS`, not `ACTIVE`.

**Reopen trigger:** when a real prayer-content cadence is authorized and can connect Scripture, actual church prayer life and distribution without duplicating church meeting notices.

The early Website channel family should be treated as a **legacy concept bundle**, not six independent active products:

- Website / 橄欖山 portal — `MAINTENANCE / HISTORICAL IA`;
- Dawn Library page — `SUPERSEDED AS ROADMAP`, folded into canonical Library workstreams;
- Daylight Café — `PARKED`;
- Newsletter — `PARKED` channel candidate;
- Podcast — `PARKED` channel candidate;
- Video — `PARKED` channel candidate;
- Watch Prayer — `PARKED / READY-TO-REASSESS` content-series concept.

No deletion is recommended. The route/content files preserve product-history provenance and may remain useful shells. Their existence must not be interpreted as current priority or completion evidence.

## Capability / lesson retained

This family teaches a reusable stewardship rule:

`route exists / placeholder exists / concept has a name ≠ active product ≠ completed product`

A future channel becomes active only after canonical intake assigns mission/reader value, dependency order, evidence needs, next milestone and a verifiable completion condition.
