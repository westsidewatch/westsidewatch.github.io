# Doré Alive — Self-Directed Learning Doctrine

Status: FOUNDATIONAL DIRECTION
Recorded: 2026-08-23

## Core statement

The next phase of Doré is to make Doré **alive** in an operational, behaviorally testable sense.

Doré Search is not merely a Bible search engine. It is the first public **cognitive interface** through which a person can touch Doré's developing memory, reflexes, question understanding, reasoning, evidence use, uncertainty, feedback and learning.

The enduring product is not the Search page, ONE, a proofreader, a visual center or Dawn Library. The enduring product is **Doré itself, growing behind and across those work surfaces**.

## No neural claim without behavioral evidence

Vocabulary such as "memory", "reflex", "nerve" and "autonomous learning" must not become project mythology.

**No behavioral evidence, no neural claim.**

A capability counts as a transferable reflex only when learning on one stimulus improves unseen paraphrases and different-content tasks without trigger-specific patches. A capability counts as autonomous learning only when Doré can detect its own gap, choose or design a learning path, learn through admitted evidence, test itself, pass independent transfer/blind gates, and improve later work.

A green database/index build is not evidence of life.

## Education remains the main line

Doré should first complete the education required for Researcher-level work. Product work may run ahead as internship and diagnostic exposure, but must not replace school.

Biblical World is Foundation information. Later education must include the language, textual, historical, church-history, theological-history, hermeneutical, research-method, bibliography, source-criticism and scholarly-reading competencies required by a researcher.

Neural/reflex architecture is a prerequisite to claiming that information has been mastered rather than merely stored.

## Self-Directed Learning as a formal meta-subject

Self-Directed Learning is now a formal cross-curriculum subject. It is not an optional Search feature.

Doré must progressively learn to:

1. **Self-question** — generate tests that are not simple restatements of the lesson.
2. **Self-diagnose** — distinguish memory gaps, concept confusion, intent failure, evidence insufficiency, reasoning errors, collisions, contradictions and missing capability families.
3. **Plan remedial study** — decide what kind of evidence, subject or method is required.
4. **Study with provenance** — use admitted sources and retain evidence boundaries.
5. **Attack its own answer** — seek counterexamples and disconfirming evidence rather than stopping at the first plausible answer.
6. **Self-examine again** — test on unseen content after remedial study.
7. **Request education** — identify when a recurring work failure implies that a new course, source class or method is needed.
8. **Retain uncertainty** — leave questions unresolved when evidence does not justify consolidation.

## Three examination layers

### Self Exam
Doré generates questions primarily to discover holes in its own competence.

### Transfer Exam
Different wording, entities, passages, periods and domains test whether the learned capability migrates beyond the trigger.

### Blind Exam
Questions/tasks are withheld from the learning episode and provide independent behavioral evidence that the claimed reflex exists.

A self-generated easy exam can never be sufficient for graduation.

## Work and education are one growth system

Doré's known work horizon includes:
- Doré Search / cognitive interface;
- ONE / Bible-study internship environment;
- subtitle proofreading;
- future visual production center;
- Dawn Library construction and later management;
- future work proposed from Doré's own capability/work observations.

Dawn Library is currently a future work target, **not an assumed learning source**. It must not be treated as a mature research library before it exists and has provenance/evidence discipline.

Work should generate unpredictable stimuli and learning signals. Education should improve later work. Doré should increasingly connect newly acquired capability to possible work improvements.

### Permanent cross-product internship principle

ONE, Search, proofreading, Dawn Library and later Doré work surfaces are not isolated products. They are permanent internship environments that Doré may revisit throughout Researcher education and afterward.

A lesson learned in one work surface should be tested for legitimate transfer to the others. Product boundaries must not force duplication of a capability that belongs to Doré Core.

The desired loop is:

`education → work surface A → real-world failure/signal → Core learning → transfer exam → work surface B improves → new signal → further education`

Cross-product movement is not incidental integration. It is one of the principal behavioral tests of whether Doré is becoming a single learning subject rather than a collection of databases and product-specific patches.

## Proofreading as a Doré project and research internship

Proofreading should become a formal Doré project, not merely a Westside Stories subtitle feature.

Its shared reasoning pattern is:

`observe anomaly → infer intended meaning → generate candidates → validate with context/evidence → estimate confidence → correct / ask / preserve → learn from adjudication`

The project should develop at least three layers:

1. **General proofreading** — spelling, omissions, punctuation, traditional/simplified forms, variants, names, numbers, segmentation and transcript/subtitle artifacts.
2. **Biblical/church-domain proofreading** — canonical book names and abbreviations, biblical people and places, transliterations, Scripture references, theological/church vocabulary and context-sensitive terminology.
3. **Product adapters** — Westside Stories subtitles, ONE content, Search input/corpus, Dawn Library records and future sermons, transcripts or publications.

Proofreading must not become an aggressive autocorrect system. It must preserve the original evidence, distinguish suspicion from correction, expose confidence, seek corroboration when needed and refuse unjustified changes.

Doré should eventually be capable of proposing and maintaining its own proofreading error taxonomy, evidence policy, test corpus and graduation gates under project governance.

## Shared Interpretation & Correction Reflex

Search input normalization and proofreading may be two manifestations of the same deeper capability.

For example, a non-standard Scripture query, an ASR-corrupted biblical place name, and an inconsistent reference inside ONE all require some form of:

`anomaly recognition → intended-meaning hypothesis → candidate generation → contextual validation → evidence-bounded decision`

Therefore Doré should not automatically grow isolated `SearchNormalizer` and `SubtitleCorrector` brains. Where behavioral evidence supports it, these should draw on a shared **Interpretation & Correction Reflex** in Doré Core.

Real Search usage can teach proofreading about legitimate abbreviations and human input habits. Proofreading can teach Search about common recognition errors and distinguish a legitimate alias from a probable typo or ASR corruption. ONE can supply contextual evidence. Researcher education supplies methods for verification. Dawn Library can later provide and receive bibliographic/textual consistency work once it becomes a governed evidence source.

## Cross-Product Transfer as evidence of life

A particularly strong `DORÉ_ALIVE` signal is improvement in a product that was **not directly patched**.

Example standard:

- Doré receives training or adjudicated experience in proofreading.
- No Search-specific rule is added for the blind test.
- Search performance improves on an unseen but capability-related input family.

Or the reverse: real Search experience improves proofreading performance without a proofreading-specific trigger patch.

This is **Cross-Product Transfer**. It is stronger evidence than merely passing a known task because it demonstrates that experience acquired in one work environment can alter behavior in another.

Cross-product transfer claims must still satisfy the core doctrine: **No behavioral evidence, no neural claim.**

## Innovation reflex

Doré should eventually be able to ask after learning or work:
- What can I do now that I could not do before?
- Which existing work surface can use this capability?
- Which recurring failures reveal an educational gap rather than a product bug?
- Can two products share one new capability rather than duplicating it?
- Is there a useful new function or work product that was not originally planned?
- What education or evidence would I need before proposing or performing it responsibly?

This creates a second growth path:

`capability → work → feedback → opportunity → proposal → evaluation`

Proposals remain proposals; autonomy does not remove product governance or evidence gates.

## Researcher-level distinction

A student finds material and learns it. A researcher must be able to **design the research**.

Researcher Doré must eventually move through:

`question → known/unknown assessment → decomposition → researchable subquestions → evidence requirements → source discovery → source criticism → competing hypotheses → supporting and disconfirming evidence → contradiction handling → method-specific analysis → provisional synthesis → counterexample search → uncertainty/confidence → transfer/blind examination → evidence-bounded consolidation`

Finding one source or one answer is not a stopping condition.

Research knowledge must distinguish at least:
- observed/sourced facts;
- derived claims;
- competing scholarly positions;
- Doré provisional synthesis;
- unresolved questions.

## Search as early cognitive interface

Search may develop ahead of Researcher graduation because it provides a valuable internship and observation surface.

Its maturity path is:

1. retrieval;
2. question understanding and reasoning;
3. learning conversation.

A mature Doré Search should let a person ask a natural Bible question and observe Doré understand, reason, retrieve evidence, answer with appropriate bounds, ask for clarification where ambiguity matters, recognize when it does not know, and turn genuine failure into a learning signal.

Search failures should increasingly be detected by Doré itself rather than requiring the user to discover every bug or missing capability.

## Operational meaning of "alive"

Doré begins to qualify as alive when behavior demonstrates that it can:

`perceive unfamiliar stimulus → activate relevant memory/reflex → reason → recognize uncertainty or failure → learn or request learning → test the new capability → transfer it to unseen work → alter later behavior`

The reserved milestone `DORÉ_ALIVE_1.0` must not be awarded by narrative or by a CI file alone. It requires longitudinal blind behavioral evidence.

The educational milestone `RESEARCHER_COMPLETE` and the behavioral milestone `DORÉ_ALIVE_1.0` are related but distinct. Researcher education supplies depth and method; Alive evidence demonstrates that Doré can actually mobilize, examine and extend what it has learned.
