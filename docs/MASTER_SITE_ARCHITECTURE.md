# Living Water Westside Watch — 主站唯一結構與功能定案

> **Status: Canonical / Current**  
> **唯一基礎文件。** 今後凡涉及 Living Water Westside Watch 的主站結構、Journal 十二欄目、三個間奏、功能上下級、跨欄目功能、搜索系統，以及這些部分如何與 Doré Core / Doré Design / Storybook 配合，均以本文件為唯一基礎。任何舊 MD、PDF、對話整理、品牌規範或工程筆記只能作歷史參考，不能覆蓋本文件。

## 0. 權威規則

1. 使用者最新明確定論高於所有歷史資料。
2. 本文件是主站**概念結構與功能邊界**的唯一權威；GitHub `main` 用來核對哪些部分已經落地。
3. **不存在「安提阿」欄目。** 舊文件中的 Antioch 一律視為歷史版本，不得恢復。
4. Journal 的 **12 個固定欄目 + 3 個間奏** 始終屬於 Journal；新功能可以調用它們，但不得因此改變歸屬。
5. 「欄目」「內容」「功能」「工具」「跨欄目服務」「設計系統」是不同層級，不能混寫。
6. Doré 不是網站。Doré 是支撐研究、搜索、內容、編輯、設計、工程、圖像與自動化的 AI / Agent 工作系統。
7. Storybook 不是黎明書局的子項；Storybook 是 Doré Design 用來訓練、驗證**整個 Living Water Westside Watch** 設計系統的環境。
8. **多雷搜索不是 AI 對話模式。** 它是獨立的搜索／檢索系統，服務聖經世界知識、主站內容以及各工具內部內容。
9. 本文件發生正式結構變更時，必須先更新本文件，再修改網站、Doré 或 Storybook 的實作。

# 1. 主站總體結構

**Living Water Westside Watch** 是網站本體。

第一級資訊架構：

```text
Living Water Westside Watch
│
├── Journal          期刊核心
├── Website          品牌內容／延伸內容
├── Church           教會生活服務
└── About            關於與網站功能資訊
```

注意：`Website` 是第一級架構名稱，不是整個網站的另一個名稱。現行 repo 中 Website 的展示名稱為 **橄欖山**。

另有一個不與上述內容樹同級的**全站功能層**，其中包括「多雷搜索」。它服務所有內容與工具，不屬於 Journal、Website、Church 或 About 任一內容欄目。

# 2. Journal

## 2.1 定位

Journal 是 Westside Watch 的期刊核心，不是普通文章列表。

它由：

- 四個樂章；
- 十二個固定欄目；
- 三個間奏；
- Vol.00 founding volume；

共同構成。

主要閱讀路徑：

```text
Cover → Opening → Contents → WATCH → WALK → WITNESS → WORSHIP
```

四樂章：

```text
WATCH      守望
WALK       同行
WITNESS    見證
WORSHIP    敬拜
```

---

# 3. Journal 十二個固定欄目

> **欄目名稱與歸屬已鎖定。** 今後只修改具體定位或功能配合時，必須在本文件記錄；不得另造第十三欄，也不得從舊文件恢復安提阿。

## I. WATCH 守望

### 1. 米斯巴 Mizpah
**定位：卷首／守望的起點。**

承擔本期開篇、本期命題、核心經文、編輯觀察與閱讀方向。它不是單純的 Editor's Note，而是把讀者帶入「站立、觀看、守望」的入口。

### 2. 伯利恆 Bethlehem
**定位：每日靈糧／A Day。**

伯利恆是永久固定欄目；其網站活體形態正式採用 **「伯利恆的一日」／A Day** 的概念。

其核心不是每天寫一篇文章，而是每天打開一頁經過預備、核對的神的話。紙本 Journal 則可從每日內容中選編一段時間的成果。

神學核心：

- 道成肉身；
- 光進入世界；
- 基督是生命的糧；
- 神的話進入人的日常。

同一內容來源可以服務 Journal、Church 今日經文以及社交媒體每日發布；但伯利恆仍然是 Journal 的固定欄目，而不是第十三個功能。

> 歷史資料能明確確認「伯利恆＝每日靈糧的母欄目」及 English `A Day`；舊資料沒有可靠地保存兩個中文候選名的原始改名記錄，因此本文件以「伯利恆的一日／A Day」作現行顯示概念，不再使用舊的「本月靈糧」定義。

### 3. The Gate 門
**定位：時代觀察／公共信仰思考／守望論壇。**

The Gate 是「大門」，不是後門。內容可包括：

- 約稿；
- 時代觀察；
- 公共信仰思考；
- 守望神學對話；
- 面向世界與教會的信仰問題。

它與何烈山的邊界：The Gate 關注**我們所處的時代與世界，以及信仰如何回應**；何烈山關注**神如何啟示自己、我們如何認識神並進入敬拜**。

### 4. 迦密 Carmel
**定位：重大特稿／本期核心 Feature / Living Feature。**

不是普通 Feature 標籤，而是內容重量容器。可以成為一期核心、重大主題或佔據大量版面的長篇內容。

---

## II. WITNESS 見證

### 5. 以斯帖 Esther
**定位：歷史見證／人物專稿。**

對象是已經走過歷史道路、留下信仰見證的人物，例如屬靈前輩、神學家、作者、牧者、宣教士及其他信仰人物。

核心是 **Past Witness**：透過人物看見神在歷史中的工作。

### 6. 亞杜蘭洞 Adullam
**定位：當代見證／人物訪談。**

對象是今天仍然活著、仍在服事的人：牧者、教會領袖、教師、宣教士、信徒領袖及忠心服事者。

核心是 **Present Witness**：生命歷程、蒙召、服事、掙扎、教會負擔與給下一代的勸勉。

以斯帖與亞杜蘭洞共同構成 WITNESS 的「歷史見證 + 當代見證」，不增加第三個人物欄目。

---

## III. WALK 同行

### 7. 西區的夜晚 Westside Night / Emmaus
**定位：同行入口／查經與共同學習工作台。**

它不是資源庫，也不是普通文章展示欄。它把 Journal 帶入實際查經與共同生活。

其工具層目前至少包括：

```text
Journal
└── 西區的夜晚
    ├── ONE
    └── 多寫
```

**ONE**：西區的夜晚的查經工具／作品之一。

**多寫**：西區的夜晚的寫作與查經工作工具。今後加入：

- 查經筆記功能；
- 查經筆記的保存、整理與回看；
- 與經文、查經內容及相關資料的關聯；
- **模糊搜索**，使使用者即使只記得部分詞語、近似詞或不完整內容，也能找回自己的查經筆記與相關內容。

多寫不是主站第一級架構，也不是 Website／橄欖山／黎明書局的子項；它是 **Journal → 西區的夜晚** 下面的工具。

### 8. 以琳 Elim
**定位：神的供應／恩典與生命。**

核心不是泛泛的「靈修」，而是神如何供應、恢復、滋養祂的百姓。內容可承載靈修、禱告、生命恢復等形態。

### 9. 別是巴 Beersheba
**定位：人的回應／盟約中的生命。**

承擔人對神恩典的回應：信靠、順服、委身、記念神的信實，以及活在盟約關係中。

### 10. 伯特利 Bethel
**定位：神家中的共同生活／教會生活。**

伯特利**不是每日靈糧欄目**。每日靈糧屬於伯利恆。

伯特利承擔：

- 教會生活；
- 團契；
- 服事；
- 彼此建造；
- 進入神的家並與神的百姓共同生活。

## IV. WORSHIP 敬拜

### 11. 何烈山 Horeb
**定位：神的啟示／認識神／因神是神而敬拜。**

核心路徑：

```text
神先看見人
→ 神主動啟示自己
→ 人看見神
→ 人成為守望者
→ 進入敬拜
```

因此何烈山不能只寫成「神學」或「神學、聖經與教義」。它不是一般讚美欄，也不是「得到祝福所以讚美」，而是「因為神是神，所以高舉神」。

### 12. 瑪拉拿 Maranatha
**定位：閉卷禱告／盼望主再來。**

不是普通結語，而是依本期主題作：

- 感恩；
- 回應；
- 代求；
- 交託；
- 等候主再來。

# 4. Journal 三個間奏

三個間奏永久存在，屬於 Journal，但不是第 13–15 個固定欄目。

```text
Journal
├── Selah／細拉
├── 遠方無聲鴿
└── 基尼烈 Kinneret
```

作用是轉調與「期刊呼吸」：

```text
WATCH → WALK       Selah
WALK → WITNESS     遠方無聲鴿
WITNESS → WORSHIP  基尼烈
```

它們可被新聞播報等跨欄目功能重新調用，但歸屬永遠不變。

# 5. 新聞播報與秒報

新聞播報不是 Journal 第十三欄，而是**跨欄目功能**。

目前組合：

```text
新聞播報
│
├── 伯利恆的一日 / A Day
├── Selah
├── 遠方無聲鴿
└── 基尼烈
```

「秒報」是新聞播報中的滾動／即時信息機制，不要求畫面每秒刷新，而是讓新信息可以持續進入、排序與更新。

其內容來源、編輯判斷與最終呈現由 Doré 工作流支援，但新聞播報本身仍是網站功能，不是新的主站內容層級。

# 9. 多雷搜索：全站搜索與知識檢索層

## 9.1 定義

**多雷搜索**是 Living Water Westside Watch 的全站搜索／知識檢索功能。

它**不是 AI 對話模式**，也不是把搜索問題改寫成聊天請求。

它的任務是：

> **讓使用者直接找到知識、內容、經文、工具資料與自己的工作內容。**

## 9.2 在主站的位置

多雷搜索不屬於 Journal、Website、Church 或 About 的任何一個內容樹枝，而是：

**全站 Global Utility Layer／全站功能層。**

它應該在主站全局可達，最合理的產品位置是：

```text
全站 Header / Utility Area
        │
        └── 多雷搜索
              │
              ├── 聖經世界知識搜索
              ├── 主站內容搜索
              └── 工具內搜索
```

搜索入口可以出現在全站 Header；結果頁／搜索面板則按搜索上下文顯示結果。它不是主站第一級內容導航項，但應當是比普通頁面更高級的全局工具。

## 9.3 三個核心搜索範圍

### A. 聖經世界知識搜索

搜索與聖經世界相關的知識，包括但不限於：

- 人物；
- 地名；
- 歷史；
- 地理；
- 時間線；
- 經文關聯；
- 聖經背景；
- Bible world knowledge。

### B. 主站內搜索

搜索 Living Water Westside Watch 本身的內容：

- Journal 十二欄目；
- 三個間奏；
- Journal 文章；
- Website／橄欖山內容；
- 黎明書局；
- 白晝咖啡館；
- Church；
- About；
- 新聞播報與已發布內容。

### C. 各工具內搜索

搜索工具自身的資料，而不是只搜索工具介紹頁：

- ONE 的內容與資料；
- 多寫的查經筆記；
- 多寫的相關內容；
- 其他未來工具的內部索引。

因此搜索結果必須能指出**來源層級**，例如：Journal、Website、Church、ONE、多寫等。

## 9.4 模糊搜索

模糊搜索是多雷搜索的核心能力，不是附加裝飾。

至少需要支持：

- 部分詞語；
- 不完整詞組；
- 近似詞；
- 中文／英文對應；
- 常見錯字；
- 不完整人名、地名或經文詞；
- 使用者記得意思但不記得精確標題的情況。

這項能力同時服務：

```text
多雷搜索
      │
      ├── 主站搜索
      ├── 聖經世界知識搜索
      └── 工具搜索
             └── 多寫查經筆記搜索
```

因此「多寫未來加入模糊搜索」與「多雷搜索實現模糊搜索」不是兩個互不相干的功能，而應共享同一套搜索能力與索引原則。

## 9.5 與 Doré Core 的關係

```text
使用者
  ↓
多雷搜索 UI
  ↓
Search / Retrieval Layer
  ├── Bible World Knowledge Index
  ├── Main Site Index
  └── Tool Indexes
        ↓
Doré Core 負責路由、檢索編排、權限／來源判斷與結果組合
        ↓
搜索結果
```

Doré Core 可以參與搜索的索引、路由、資料理解與結果排序，但**搜索請求本身不因此變成 AI 對話**。

只有使用者明確進入 AI 對話或其他 Agent 工作流時，才進入對話模式。

## 9.6 與內容架構的關係

多雷搜索可以穿透整個內容樹：

```text
Living Water Westside Watch
│
├── Journal ───────────┐
├── Website ───────────┤
├── Church ────────────┤ → 多雷搜索 → 結果按來源分組
└── About ─────────────┘
                         │
                         ├── ONE
                         ├── 多寫
                         └── 其他工具
```

因此搜索是**跨層能力**，不是新的內容層。

# 10. 多寫與多雷搜索的專門配合

多寫目前屬於：

```text
Journal
└── 西區的夜晚
    └── 多寫
```

未來「多寫」增加查經筆記後，資料模型應至少能保存：

- 筆記內容；
- 關聯經文；
- 關聯書卷／章節；
- 建立／修改時間；
- 標籤或主題；
- 關聯查經材料；
- 可搜索文本。

多寫的搜索優先使用多雷搜索提供的模糊搜索能力，而不是另造一套互不相容的搜索算法。

# 11. Doré / Doré Core / Doré Design / Storybook 的配合

## Doré

Doré 是整個系統的工作／Agent 層，不是主站。

## Doré Core

負責跨功能的核心編排，包括搜索、知識路由、內容理解、工作流與 Agent 協作。

## Doré Design

負責網站與產品設計系統、組件、視覺規則以及與 Storybook 的設計驗證。

## Storybook

Storybook 的訓練範圍是整個 Living Water Westside Watch，不是黎明書局。

```text
Storybook
├── Homepage
├── Journal
│   ├── 12 欄目
│   └── 3 間奏
├── Website / 橄欖山
├── Church
├── About
├── 多雷搜索
└── 其他全站功能
```

任何主站 UI／UX 新功能，包括多雷搜索，都必須在這個全站設計系統中考慮，而不能只在某個工具內孤立設計。

# 12. 功能、欄目與工具的判斷規則

新增任何東西時，先判斷它屬於哪一層：

```text
欄目       = Journal 的固定編輯位置
內容       = 某欄目產生的具體作品
工具       = 為某一工作場景提供操作能力
功能       = 可以跨欄目／跨工具工作的服務
產品       = 可獨立使用的一組工具與內容
全站功能   = 不屬於內容樹、但全站可使用的能力
設計系統   = Storybook / Doré Design 的驗證範圍
```

例如：

- 伯利恆 = 欄目；伯利恆的一日 / A Day = 其網站活體形態。
- 西區的夜晚 = 欄目；ONE、 多寫 = 其工具。
- 查經筆記 = 多寫的新功能，不是新的 Journal 欄目。
- 多雷搜索 = 全站功能，不是 Journal 欄目。
- 新聞播報 = 跨欄目功能，不是第十三欄。

# 13. 唯一變更流程

今後任何人／Agent 要修改主站結構，必須：

```text
提出變更
  ↓
讀本文件
  ↓
判斷變更屬於：欄目／內容／工具／功能／產品／全站功能／設計系統
  ↓
確認父子層級與既有邊界
  ↓
若是正式定案：先更新本文件
  ↓
再更新網站、Doré Core、Doré Design、Storybook 或工具實作
  ↓
驗證實作沒有違反本文件
```

任何工程任務都不得直接把自己的局部實作當成新的主站結構。
