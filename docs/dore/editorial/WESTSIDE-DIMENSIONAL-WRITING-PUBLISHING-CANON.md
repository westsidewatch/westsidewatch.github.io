# 西望立體寫作 & 出版系統

Status: Core capability seed / site-wide canon
Capability: `publishing.dimensional-writing`

這不是文風筆記，也不是 Journal 特例。它是多雷 Core 的寫作、研究、編輯、感知設計與出版能力，輸出同一份 canonical publication plan，供 Journal、黎明書局、ONE、多寫（Doré Folio）與正式圖書共用。

## 目的

一份半成品書稿進入系統後，不需要重新發明「怎麼成為特稿、怎麼配圖、怎麼浮現、怎麼成書」。多雷先保留作者原稿與 thesis 的 authority，再做深挖、擴散、證據化、感知化、回流與出版編譯。文章可以成為 Journal 特稿；研究來源沉澱為 Dawn Research Collection；人物、作品、概念、古卷、地點與相關專稿形成 Contextual Emergence；同一 canonical plan 再交給多寫「成書」完成圖書出版。

## 西望寫作運動

`發現 → 深挖 → 擴散 → 感知 → 漫遊 → 暗線 → 收攏`

這不是正文模板。讀者不應看見七步。它是編輯與多雷背後的工作方式。核心判準：**出去多遠不代表文章多深；能把多遠的東西帶回來，而且使出發的經文、人物或問題比原來更亮，才叫深。**

每一次擴散都必須埋著回來的理由。地圖、史料、原文、學者、藝術、聲音、互動不能作裝飾；若刪除後不損失理解，它就不應存在。

## 立體維度

多雷對每一個重要判斷主動檢查：原文與文本、歷史、地理、人物、作品、接受史、歷代神學、現代研究、反方／限制、手稿與原典、地圖、藝術、聲音與朗讀、可視化資料。不是每篇全部使用；只有能建立閱讀、並能收攏回主題的維度進入成品。

凡正文作出審美判斷，編輯應盡可能把證據變成可感知經驗。例如說《約伯記》是偉大詩歌，不能只列名人評價：應選取希伯來詩句，展示聲音、平行、重複、意象與翻譯差異；必要時讓讀者聽見原文。說烏斯在何處，地圖必須參與論證。說歷代藝術家如何閱讀約伯，Blake、Doré 等作品必須作為視覺閱讀而非配圖。

## Contextual Emergence / 語境浮現

浮現是全站能力，不是 tooltip。正文第一次遇到陌生人物、作品、概念、古卷、地點、藝術品、研究來源或另一條已成形的文章礦脈時，讀者可在不離開正文的情況下得到：圖像／肖像、作品圖、極短身份、此刻為何出現、關鍵原典／研究，以及「進一步研讀」入口。

Canonical identity 與 contextual presentation 分離。同一位愛任紐只有一個人物身份，但在不同文章中「此刻為什麼遇見他」不同。再次點擊可進入完整人物／作品研究頁，連到 Dawn 藏書、原典、相關 Journal、Shadow Record、ONE 等。

## 視覺與製圖

西望沒有單純的「配圖」。只有視覺證據、視覺敘事與視覺閱讀。多雷在決定插圖前先探索當前任務所需的圖像方法與生成提示策略，對成熟提示方法做 provenance-aware 比較，再編譯為當前作品專屬的 image brief；不得把網路提示詞直接拼貼進生成。Image capability 只接收經 Editorial Core 批准的 brief，並保留來源、意圖、版權／公版狀態與用途。

## 出版編譯

同一 Publication Plan 可投影到不同 Surface：

- Journal：正文、浮現、地圖、聲音、視覺證據、延伸專稿。
- Dawn：Research Collection、人物／作品／原典／來源關係。
- ONE：經文、原文、正典互文與查經入口。
- Doré Folio：保留同一研究與身份 substrate，進入「成書」。
- Book：章節、圖版、註釋、索引、bibliography、電子書／印刷所需資產。

Surface 不另建第二套內容身份。

## 約伯：第一個能力驗收樣本

輸入一篇未完成的約伯稿，系統不只補「約伯預表基督」。它應能發現並評估：烏斯的地理爭議與地圖；故事年代與成書年代不可混同；希伯來詩歌可展示與朗讀的段落；古代近東背景；世界文學接受；重要研究；Blake/Doré 等視覺閱讀；約伯 9、16、19 章中仲裁者／見證者／救贖者語言；哪些擴散最後能回到「兩造按手」以及新約唯一中保。不能收回的有趣資料不得因為有趣而進正文。

驗收不是「資料多」。驗收是：讀者經過遠行後回到約伯 9:33，那句話比出發時更重；進入提前 2:5 時，不像串珠貼經文，而像古老呼喊終於得到回答。

## 多雷訓練判準

多雷審稿／成書前必須能回答：

1. 這個判斷讓讀者親眼看見／聽見了嗎？
2. 深挖是否跨出了真正有價值的維度？
3. 每次擴散為何存在，最後回到哪裡？
4. 圖像、地圖、聲音、原文是否參與論證？
5. 被引用人物是否可浮現並繼續研讀？
6. Claim Ceiling 是否與證據匹配？
7. 作者原意是否被保留，而非被模型重寫？
8. Journal、Dawn、ONE、多寫、Book 是否共用同一 canonical identity？
9. 成品是否比輸入更立體，但負擔更小？
10. 對神學／聖經文章：最後是否使人更多看見主耶穌基督，而不是更多看見作者的知識？

## 系統原則

能力越大，作者與讀者負擔越小。深度沉在 Core；Surface 只在需要時浮現。研究不堆在正文，正文也不因流暢而犧牲研究。多雷負責把複雜度吸收進底層，讓出版變得更自然。

本 canon 與 `local/dore-local/dimensional_publishing_capability.py` 及 `dimensional_publishing.schema.json` 同步演進；MD 只記錄人類可讀規則，機器能力與 schema 才是執行 substrate。
