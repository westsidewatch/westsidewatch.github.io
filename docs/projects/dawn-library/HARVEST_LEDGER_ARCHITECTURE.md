# Dawn Library — Incremental Harvest Ledger Architecture

Status: authority for autonomous collection growth

## Ownership boundary

Dawn Library storefront is a consumer of Resource Fabric. Autonomous harvesting MUST NOT own or mutate storefront presentation, homepage navigation, Living Wall state, or an arbitrary current development branch.

Only Promotion may create or update canonical Works.

## Pipeline

Source Adapter → Harvest Ledger → Normalize → Identity/Dedupe → Qualification → Edition/Rights → Promotion → Canonical Work → Resource Fabric → Consumers

### 1. Source Adapter

Each reliable repository is registered once. Prefer structured bulk/incremental interfaces over repeated search-page discovery: OAI-PMH, MARC exports, RDF/JSON feeds, repository dumps, stable APIs.

### 2. Harvest Ledger

Persistent state is keyed by source and partition. Minimum fields:

- sourceId
- partition/set
- cursor or resumptionToken
- lastSuccessfulHarvest
- lastDatestamp
- sourceRecordId
- contentFingerprint
- identityFingerprint
- disposition: unseen | normalized | duplicate | qualified | deferred | rejected | promoted
- dispositionReason
- retryAfter / retryPolicy
- canonicalWorkId when resolved

The ledger is operational state, not bookstore content.

### 3. Incremental rule

A normal run starts from the saved cursor/datestamp. Previously terminal duplicate/rejected records are not re-evaluated unless their source fingerprint changes or the qualification policy version changes. Deferred records are retried only when retry policy says they are eligible.

Full rescans are explicit maintenance operations, never the default autonomous mode.

### 4. Normalize and identity

Normalize metadata before qualification. Identity/dedupe runs before expensive edition/rights work. Existing canonical Works are matched rather than copied into a second catalogue.

### 5. Qualification

Qualification answers whether a record belongs in Dawn Library. It does not publish the record. Reasons must be machine-readable so throughput can be measured by rejection/defer cause instead of regenerating prose reports.

### 6. Edition / rights

Resolve a usable edition and reading pointer where required. Failure here produces a specific deferred state rather than returning the record to discovery.

### 7. Promotion

Promotion is the only write boundary into canonical collection data. A promoted item receives/resolves canonical identity and enters Resource Fabric. Consumers discover it through Resource Fabric; no storefront-specific copy is generated by the harvester.

## Throughput rules

Measure every run as:

harvested → new → normalized → deduped → qualified → edition-ready → promoted

Also record cache hits and skipped terminal records. A run that scans thousands but produces one new candidate must expose whether the bottleneck is source exhaustion, cursor failure, dedupe, qualification, edition/rights, or promotion.

Known-source harvesting and new-source discovery are separate jobs:

- Known-source harvesting: frequent, incremental, high-throughput.
- New-source discovery: lower-frequency; discovers/registers repositories and adapters, not individual bookstore cards.

## Git write isolation

Harvest/discovery jobs MUST NOT `git push` to the checked-out/current branch.

Operational ledger/report output belongs to an isolated autonomous-growth state target or CI artifact/store. Canonical collection changes are emitted only by Promotion and enter the normal reviewed/gated integration path.

No autonomous job may append commits to a developer PR head merely because Actions checked out that ref.

## Compatibility with current Dawn structure

Preserve:

- canonical Works
- Resource Fabric identity
- classification
- covers
- reading pointers
- search indexes
- Traditional Chinese reading capability

Do not reintroduce presentation concepts such as 黎明選讀, 館藏流, Living Wall, tracks, timers, or homepage animation into the growth pipeline.

## Mature patterns being absorbed

The implementation should absorb, not vendor wholesale:

- Metafacture-style modular metadata transformation pipelines.
- OAI-PMH selective/incremental harvesting with datestamps, sets and resumption tokens.
- VuFindHarvest-style persisted harvest state, resume and deleted-record handling.

Dawn canonical identity and Resource Fabric remain the authority.
