# Doré Skill Growth — Observation Layer v0

This layer closes the missing `observe -> detect gap` segment of the existing Doré Evolution spine. It is not a second evolution pipeline and it does not replace the Capability Registry.

## Flow

`Work Event -> Observation -> Pattern/Friction -> Capability Gap -> Skill Candidate -> Exploration/Sandbox -> Evaluation -> Promotion Gate -> Capability Registry -> Work`

## Authority boundary

An Observation is evidence, never canonical capability authority. Observation generation and candidate research may be autonomous. No Observation or Candidate may promote itself into the Capability Registry, rewrite human authority, or claim PASS without external evaluation evidence.

## Observation classes

- `correction`: a human or authoritative correction to Doré behaviour.
- `failure`: an attempted execution that failed its acceptance boundary.
- `friction`: repeated manual work, avoidable intervention, or unstable behaviour.
- `success-pattern`: a method that repeatedly succeeds and may transfer.
- `capability-gap`: work required a capability that the current system could not invoke.
- `transfer-signal`: a local rule appears applicable to sibling skills or other capabilities.

## Growth rule

One observation is not automatically a Skill. Repetition, transferability, severity, or an explicit authority principle can justify escalation. The next layer clusters observations and distinguishes a local defect from a reusable capability.
