# Doré visual canvas architecture — retained knowledge

Status: executable architectural rule, not a project note.

## Selection constraints

Doré prefers: free/permissive, local-first, small dormant footprint, stable upstream, fast integration, deterministic state, replaceable renderer.

## Mature patterns absorbed

1. **Application state is the source of truth.** Konva's own best-practice guidance recommends keeping application state separately rather than treating the canvas node tree as persistent application state. Doré therefore owns workspace JSON; Konva is an interactive projection of it.
2. **Asset and shape are separate.** Generated bytes become a durable asset record. Placement becomes an image shape referencing `asset_id`. Regeneration can replace an asset without inventing a second design system.
3. **Images are normal shapes.** Once accepted by Image critic, an image enters Design as a normal image shape with geometry, fit, role and transform state. No manual download/upload boundary.
4. **Canvas engine stays replaceable.** Konva may provide interaction, hit-testing, drag and Transformer handles. Doré's schema must not persist Konva-specific objects.
5. **Deterministic export remains separate.** Existing SVG/export verification stays authoritative where possible. Canvas screenshots are visual evidence, not persistent state.
6. **Load image bytes explicitly.** Canvas libraries do not serialize image objects reliably. Resolve `asset_id -> uri/bytes` at render time.
7. **Normalize transforms back into Doré geometry.** Konva Transformer changes scale values; on transform end Doré compiles scale into canonical `x/y/w/h/rotation` and resets view-only scale.
8. **CORS is part of the asset contract.** Browser canvas export fails when remote images taint the canvas. Doré local assets should be served from the same loopback origin or with explicit safe CORS.
9. **Memory is bounded.** Load only assets visible in the active page; release image objects when pages are inactive. Do not preload the asset library.

## Native state contract

`Generated image -> DesignAsset -> DesignImageShape -> workspace -> interactive canvas view -> canonical geometry patch -> workspace -> deterministic export/visual verification`

The first native records are implemented in `dore_core.capabilities.image_handoff` as `DesignAsset` and `DesignImageShape`.

## Dependency policy

Konva is an optional interaction engine, not Doré's brain and not Doré's storage format. Do not add React/Vue/Svelte wrappers. Use vanilla Konva only if/when the existing Design UI needs interaction beyond its current DOM/SVG implementation. SVG remains available for deterministic export. This preserves low footprint and avoids framework lock-in.

## Rejected directions

- Persisting `stage.toJSON()` as Doré workspace state.
- Making ComfyUI, Konva, tldraw or Polotno the owner of Doré design state.
- Manual generated-image download/upload between Image and Design.
- A separate Image agent and Design agent exchanging prose.
- Loading a large editor SDK merely to obtain image placement and resize.
