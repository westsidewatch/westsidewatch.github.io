# CITY-MASS-01C：首次生成與回訪快取量測

本包建立量測基準，不改城市形狀、位置、年代、快取容量或載入策略，也不宣稱已縮短等待。

## 計時範圍

- persistent city world：分開記錄同步建造、資料登錄、幾何去重及本次 activate 的快取命中／耗時；每個時期的首次紀錄保留，回訪不覆寫。檢查工具拿到的是副本。
- shared era runtime：記錄地塊計算、包含讓出主執行緒的住宅建造牆鐘時間、登錄／道路／投影收尾，以及從 request 到 ready 的總牆鐘時間。頂層顯示目前作用中的住宅來源，避免把第一聖殿的計時誤讀成波斯或希臘時期。
- 瀏覽器：新開一頁依序走18期，再反向回訪18期；記錄自動操作至可檢查且經過兩幀的牆鐘時間。這包含工具與渲染開銷，不等於純建造時間，也不是 GPU 完成或視覺品質的驗收。

## 初次本機量測

1200×900、headless Chromium、reduced motion、單一新頁。初始 ready 約1.26秒。以下只是本機觀察，不設毫秒效能門檻，不保證使用者裝置或網路有相同速度。

| 時期 | 首次操作至穩定 | 同頁回訪 |
|---|---:|---:|
| 晚期第一聖殿 | 1170ms | 301ms |
| 波斯 | 474ms | 211ms |
| 希臘／哈斯摩尼 | 1362ms | 268ms |
| 希律 | 553ms | 290ms |
| 奧斯曼 | 1009ms | 201ms |
| 現代 | 1100ms | 222ms |

後期八個時代總共只建造八次，反向回訪保留相同 Mesh／Geometry 身分；快取已在工作，不能以「每次都重新建城」解釋所有等待。後期建造約118–383ms／期，登錄約10–16ms、去重約19–35ms；住宅建造是這條同步路徑的主要成本。共享希臘住宅建造含排程讓出約771ms，request 到 ready 約1030ms。

## 下一包施工依據

優先將後期同步建造改為可取消、分段且完成後原子切換的工作，限制長任務並維持建造完成後才播放的規則；先驗證城市數量、位置、證據、快取身分與快速來回切換。不要先刪除地形、縮放住宅、預載全部年代或擴大細節量。
