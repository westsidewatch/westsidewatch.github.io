# F2 第一包：共同地表與18期骨架入口

2026-10-23，沿用 fa588872d 以前的地形、模型及共同物件帳本。此包是全線基礎接入的第一步，並未完成全部時代的物件發布或17段歷史變遷。

## 直接修正的全線斷點

1. 舊遺存層從整個場景向下射線取高度，可能讀到其他建築、甚至隱藏建築的屋頂。現在強制由主場景注入共同DEM，取消場景射線取地形。缺少共同地形時明確失敗，不另造平地。
2. 地表取樣此前有兩種算法：一般高度API使用四點雙線性內插，早期聚落和王城使用實際渲染三角形。鞍形格內兩者可不同。現在共用同一三角形取樣函式，地圖座標取高也經同一API；DEM頂點、datum與垂直比例均不變。來源邊界僅容許Float32網格的微小捨入誤差，真正越界回傳NaN。
3. 十字軍與奧斯曼生成器的進度，誤接在希律／羅馬毀城的standing參數上；後期standing為0，既有量體因此停在零建造進度。現在非希律核心時代使用自身localProgress。這會恢復既有模型顯示，沒有新增或認證建築形制。

4. 撤除未定位錨點的雜湊盒形／平台顯示，防止巨型占位板遮蓋城市與山地。來源帳本和已有時代模型保留；待定位資料不以假幾何填補。

## 共同入口與檢查契約

city-foundation-runtime.js 明列18期的主要生成入口，依序檢查完整覆蓋；主場景重建調度使用這份入口分流。各生成器繼續重用既有模型，不複製成另一套城市。投影與檢查介面共用物件ID解析，既有 parcelId→building 的隱式綁定也按原契約辨認，避免把已接入的希律住宅誤列成未入帳。

檢查介面列出六類骨架：住區、路徑、水防、聖域／公共核心、聚居、生命週期。它讀取當下共同核心，並比對實際可見的模型綁定；子構件數與獨立物件數分開計算。缺口包括：未登記量體、未有生命週期事件、跨期錯配，以及舊比例遺存層。後者維持明確的示意身分，不因此獲得已核定的生存或再利用關係。

後期 fallback 住區量體原本沒有工程標記，現加上「未登記示意幾何」標記供檢查。另有舊錨點顯示按ID雜湊產生位置和大型盒形／平台，並非來源定位；驗收發現它們會遮住城市，故撤除該顯示路徑，保留帳本資料。沒有將盒形變成已核定的 semantic building，也沒有為填滿六類統計而捏造城牆、路網或地標。

開發檢查API：

- window.__JERUSALEM3000__.cityFoundationIndex：18期入口、前後期與共同地形契約。
- window.__JERUSALEM3000__.inspectCityFoundation()：目前時代六類登記範圍、可見綁定與未接入構件。
- inspectCityFoundation(phaseId)：非目前時代只讀已登記範圍，模型欄位為null，不觸發生成。

所有輸出 foundationAccepted:false。零登記量不能解釋為歷史不存在；目前畫面有模型也不代表已完成城市骨架。按需檢查才掃描可見模型，不在每個畫面重掃全城；普通診斷只保留輕量入口描述。輸出不含可變的帳本／網格參照。

共同取高一致不代表每個大型量體的所有角點／基座都已貼合坡面；那仍須在骨架配準驗收中檢查。約90m的現代DSM也不能因此成為古地表認證。

## 驗證與下一步

單元檢查涵蓋18期錯序／漏期、同一地形實例要求、鞍形DEM三角形取樣、來源四角／真正越界、未入帳與比例遺存分開計數、祖先隱藏、非當期只讀、輸出修改不影響帳本。加入高屋頂後，遺存幾何的位置必須與未加屋頂前完全相同；釋放遺存層不能移除共同地形。

瀏覽器逐一檢查18期的六類欄位與真實可見構件；十字軍／奧斯曼在各自晚段必須有既有主要量體。既有王城高差、住宅身分、毀壞／反轉、直向畫面及完整性界線仍在全線回歸範圍內。

下一包 F2：按介面輸出的缺口，先接入早期聚落與後期示意層的穩定物件身分、來源及明確「未知去向」；再補不足的住區／道路骨架，進入F3的17段變遷。暫停門窗、柱式、屋頂紋理等細化。既有比例保留不等於已核定繼承，必須後續用物件事件替換，不能由這個檢查介面自動補造。
